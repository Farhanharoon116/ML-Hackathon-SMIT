# Food Delivery Analytics Challenge

Python/Pandas analysis of 38,964 food-delivery records to find what slows deliveries down, plus an optional machine-learning extension that predicts delivery time.
Workflow: Load → Clean → Analyze → Visualize → Interpret → Explain → (Bonus) Predict.

## Project structure
```
├── data/food_delivery.csv
├── food_delivery_analysis.ipynb   # full solution
├── charts/                        # generated by the notebook
├── ai_explanation.txt             # generated by the notebook
├── requirements.txt
└── README.md
```

## How to run
```bash
pip install -r requirements.txt
export GROQ_API_KEY="your_key"     # Windows PowerShell: $env:GROQ_API_KEY="your_key"
jupyter notebook food_delivery_analysis.ipynb   # Run All
```
In Google Colab, add `GROQ_API_KEY` under the Secrets (key icon) panel and enable notebook access.
The API key is read from the environment (or a local `.env`); it is never hard-coded.
Without a key, the AI cell prints the prompt instead of failing.

## Data cleaning decisions
| Problem | Decision |
|---|---|
| Duplicate rows | Dropped |
| Placeholder strings (`"NaN "`) and stray whitespace | Stripped, converted to real missing values |
| Prefixes (`conditions Sunny`, `(min) 24`) | Removed |
| Wrong types (age, ratings, multiple_deliveries, time as text; date as text) | Converted with `pd.to_numeric` / `pd.to_datetime` |
| Invalid values (rating outside 1–5, age outside 18–65, distance ≤ 0, time ≤ 0) | Rows removed |
| Missing age / ratings | Filled with median (robust to outliers) |
| Missing weather, traffic, city, festival | Filled with mode |
| Missing `multiple_deliveries` | Filled with 0 |
| Missing `Time_Orderd` | Kept in the analysis; in the ML section the order hour is filled with the median |
| `delivery_speed` | Recomputed as distance_km / (time / 60) for consistency |

## Answers
All three answers are computed in code (none hard-coded); see section D of the notebook.

- **Q1:** Traffic: 'Jam' traffic averages 31.4 min vs 21.5 min in 'Low' traffic (46% slower). Business meaning: add dynamic ETAs, route around congestion and shift staffing to peak-traffic zones. 

- **Q2:** Distance: each extra km adds about 0.54 min (r=0.32). Business meaning: price delivery fees by distance band and limit the radius of very long orders to protect delivery promises.

- **Q3:** Weather x traffic: 'Fog' + 'Jam' is the worst combination at 36.9 min (39% above the overall average of 26.6 min). Business meaning: add surge incentives or extend ETAs in this situation.

## Bonus: Machine learning (section H)
Machine learning is not required by the challenge; it is an extension. The core analysis above is done entirely in Pandas.

**Goal:** predict `Time_taken (min)` (regression).

**Features:** rider age and rating, distance, number of simultaneous deliveries, vehicle condition, order hour and weekday (engineered from `Time_Orderd` and `Order_Date`), traffic, weather, order type, vehicle type, festival, city.

**Encoding**
| Column type | Columns | Method | Why |
|---|---|---|---|
| Ordinal | `Road_traffic_density` | `OrdinalEncoder` (Low < Medium < High < Jam) | order carries meaning |
| Nominal | weather, order type, vehicle type, festival, city | `OneHotEncoder` | no natural order, avoids a false ranking |
| Numeric | age, rating, distance, etc. | passed through | already numeric |

Encoders sit inside a scikit-learn `Pipeline` / `ColumnTransformer`, so they are fitted on the training set only (no data leakage).

**Leakage prevention:** `delivery_speed` is derived from the target and is excluded from the features.

**Models compared** (80/20 train/test split, `random_state=42`): mean baseline, Linear Regression, Random Forest, Gradient Boosting.
Metrics: MAE, RMSE, R², plus 5-fold cross-validated R² for the best model.

**Results**:
| Model | MAE (min) | RMSE (min) | R² |
|---|---|---|---|
| Baseline | 7.431 | 9.226 | -0.000 |
| Linear Regression | 4.749 | 5.943 | 0.585 |
| Random Forest | 3.069 | 3.858 | 0.825 |
| Gradient Boosting | 3.062 | 3.816 | 0.829 |

**Interpretation:** permutation importance shows which factors matter most, and a what-if table shows how the predicted time changes when only traffic changes.
